OpenInsert 0.3.2 fixes unwanted Chinese segmentation spaces and the extra blank Settings window. These changes build on the previous public release, 0.3.0, and include the spacing correction previously tested in the unreleased 0.3.1.

- **Chinese spacing:** Traditional and Simplified Chinese writing preferences remove isolated spaces between Chinese characters and selected Chinese punctuation. The same local formatting applies to live previews, finalized text, successful cleanup and cleanup fallback, including **Verbatim mode**. It makes no additional API request. Raw provider segments remain unchanged, and formatting never promotes an interim preview to a final transcript.
- **Preserve intentional spacing:** English/number boundaries, line breaks, tabs, repeated spaces, inline/fenced/indented code, and lines containing Japanese kana or Korean Hangul retain their spacing. Automatic and other non-Chinese preferences remain unchanged. This is conservative formatting, not a full Markdown parser.
- **One settings window:** Settings, Command-comma and reopening the app now show the existing main window instead of creating an empty SwiftUI Settings window. Closing the window leaves the menu bar app running. Native editing/window menus and waiting for clipboard restoration before quitting are retained.

**Verified:** 149 XCTest cases passed, alongside typechecking, universal builds and strict code-signature checks. Tests cover spacing, language preferences, protected content and Live transcript finality. Installed-app UI checks confirmed settings/reopen behavior, editing commands, Undo/Redo, Enter to save a shortcut and Escape to cancel. Existing settings and permissions were preserved in the tested local update. The user initially reported that the spacing problem no longer occurred after the included 0.3.1 fix.

**Release artifacts verified:** Both GitHub workflows passed on release commit `b8c1925`. The downloaded ZIP and DMG match the SHA-256 manifest and GitHub asset digests; archive integrity, strict app signature, version 0.3.2/build 14, both CPU architectures, macOS 13 minimum and bundled localization resources were checked. The public package was not installed or run during this artifact verification.

These results are not comprehensive voice or cross-app validation. The 0.3.2 window update was not followed by another real microphone/Google dictation test. Physical hold/tap combinations, keyboard layouts and destination apps still need broader testing. See the [validation report](https://github.com/Buffett111/OpenInsert/blob/main/docs/VALIDATION.md).

**Download:** universal Apple Silicon/Intel builds for macOS 13 or later. This remains an **ad-hoc-signed, unnotarized community prerelease**, not a Developer ID release. Intel is cross-compiled, not runtime-tested.
