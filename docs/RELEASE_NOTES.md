OpenInsert 0.2.3 is an early macOS release of an MIT-licensed, Gemini BYOK dictation app.

This release separates ASR finalization from optional text cleanup and fixes a completion condition that could leave dedicated Live transcription waiting for 20 seconds.

- For the exact default `gemini-3.5-transcribe-live`, completion no longer requires the conversational `turnComplete` event. It requires authoritative `inputTranscription` text, a successfully sent `activityEnd`, no unresolved interim text, and one second without transcript updates. Other model IDs retain the additional `turnComplete` requirement. The 20-second ASR deadline remains; interim text is never promoted to final text.
- Default cleanup uses `gemini-3.5-flash-lite` with `thinkingLevel: minimal`. Other Gemini 3 model IDs retain `low`; Gemini 3.8 does not support minimal. See [Google's thinking table](https://ai.google.dev/gemini-api/docs/generate-content/thinking#thinking-levels-gemini-3).
- Cleanup has an independent eight-second total deadline and can be skipped while waiting. A skip or temporary cleanup error (timeout, network failure, HTTP 429 or 5xx) uses the finalized ASR text after the normal target checks and reports the fallback. Cancelling the whole dictation, permanent errors, blocked responses and incomplete/invalid output do not trigger automatic insertion. Late responses cannot overwrite the selected result.
- The interface distinguishes ASR finalization and cleanup, with separate elapsed times.
- Input capture now reports the actual Accessibility permission or focus error. Supported Electron apps can prepare their native Accessibility bridge when activated; insertion still requires an editable focused field and revalidates the original target.
- Recovers delayed shortcut releases using limited background key-state checks with an existing Accessibility grant. Carbon remains primary; the check only samples Space and the registered modifiers while a press is outstanding. Ambiguous hold/tap timing cancels dictation and asks for a retry. No keyboard event tap, all-key monitor or new Input Monitoring request is added.
- Adds a writing-language menu: Traditional Chinese (Taiwan), automatic, Simplified Chinese, English, Japanese, Korean, or custom. ASR continues to detect spoken languages automatically; choices preserve mixed-language speech and do not request translation. Chinese character forms are converted locally, including live previews. Existing custom preferences are retained.
- Adds **測試辨識與後修（不錄音）**: after saving a key and enabling Google consent, a fixed sentence is synthesized in memory and sent to the selected Google ASR model, then its transcript is tested with the selected cleanup model and empty vocabulary. It reports the two stages separately without microphone capture or text insertion. This is a real API request and can incur charges; it does not test the user's voice or destination app.
- The installed executable also accepts `--diagnose-pipeline` for that fixed-sentence test. It requires prior key/consent setup, has a 70-second overall deadline, prints only a JSON status/timing report and synthetic result, then exits. Redirecting stdout can retain the test report.
- Local source builds can reuse an existing signing certificate through the gitignored `.local-signing-identity` fingerprint selector; `CODE_SIGN_IDENTITY` takes precedence. A stable Apple Development identity can help preserve local permission grants across rebuilds. This adds no Developer ID signature or notarization; public CI still defaults to ad-hoc signing without a local identity file.

Existing features remain: Option + Space hold/tap dictation, nonactivating floating subtitles, safe opaque-key validation, a no-audio connection check, custom vocabulary, and focus-aware AX/clipboard insertion with guarded clipboard restoration. The default ASR and cleanup IDs match the settings observed in Dup 1.20260913.0; that does not establish identical prompts, processing behavior or recognition quality. See [Dup evidence](DUP_MODELS.md).

Raw 16 kHz mono Int16 microphone audio streams to Google while speaking, using bounded RAM buffers with failure on overflow. No recording files, screen capture, analytics, OpenInsert account or persistent transcript history are created. The API key stays in macOS Keychain. Cancelling cannot recall data already sent. See [privacy](PRIVACY.md).

**Known limitation:** the official input-transcription protocol does not provide a guaranteed ordering barrier for every late segment. The one-second quiet rule remains a heuristic. The earlier 20-second error identifies ASR finalization, not Flash Lite latency. Actual test counts, synthetic API diagnostics, microphone checks and cross-app insertion results are listed separately in [validation](VALIDATION.md); passing local tests does not establish real-service compatibility or recognition quality.

Requires macOS 13+, your own compatible Gemini API key, cloud consent, and microphone/Accessibility permissions for ordinary dictation and insertion. Upgrading from 0.1 requires new consent because audio leaves the Mac during recording. ASR and cleanup have separate model fields; the old 0.1 default migrates to the cleanup default while other custom models are retained.

This early community build is **ad-hoc signed, not Developer ID signed or notarized**. Updating may require granting Accessibility again for the current app. macOS may block downloaded builds; use [Apple's official guidance](https://support.apple.com/en-us/102445) and [installation instructions](INSTALL.txt). Do not disable Gatekeeper.
