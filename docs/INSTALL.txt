OpenInsert 0.3.0 — macOS 13 or later
Community prerelease: ad-hoc signed and not notarized.

1. Drag OpenInsert.app to Applications.
2. Open it and save your own Gemini API key in Connection & Permissions.
   Paste the complete opaque key, including punctuation. Local validation checks
   header safety, not Google's authorization, billing or model access.
3. Enable microphone and Accessibility permission for OpenInsert.
4. Agree to live audio streaming and optional transcript cleanup by Google.
   Upgrading from 0.1 requires new consent; audio is sent while you speak.
5. Quit other apps that use Option + Space. Focus a text field.
6. Hold Option + Space, speak and release. Or tap once to start and again to stop.
   A hold of at least 0.35 seconds finishes on release. Shortcut conflicts show an
   error; quit the other app or choose an alternative shortcut in settings.
   If release timing is ambiguous, OpenInsert cancels and asks you to retry. With
   Accessibility already granted, it can check only the shortcut's key states to
   recover a delayed release; it does not monitor all keyboard input.
7. The floating panel shows live text, state and errors without taking focus.
   "預覽浮動字幕" uses synthetic text only: no microphone, network or insertion.
8. Choose a writing-language preference: Traditional Chinese (Taiwan), automatic,
   Simplified Chinese, English, Japanese, Korean or custom. ASR still detects spoken
   languages automatically. Chinese forms are converted locally, including previews;
   mixed-language speech is preserved and the menu does not request translation.
9. Switch the interface between English and Traditional Chinese with the language
   picker at the bottom of the window. This is separate from writing preferences.
10. In Preferences, choose Change shortcut, press a combination and save it.
    General keys require Command, Option or Control; F1–F20 may be used alone.
    Escape cancels. A conflicting candidate does not replace the saved setting.

The compact floating panel has a green waveform driven by microphone volume,
with the live transcript below it. Its width adapts to the available screen.

Optional checks after saving the Keychain key and enabling Google consent:

- "檢查 Gemini 連線（不錄音）" contacts Google with the selected Live model and
  fixed setup settings, then closes the session. It sends no audio or custom
  vocabulary and never opens the microphone. Success verifies connection/model
  setup only, not ASR, cleanup or insertion.
- "測試辨識與後修（不錄音）" synthesizes a fixed sentence in memory, sends that
  audio to the selected ASR model and tests the resulting text with the selected
  cleanup model. Custom vocabulary is empty. This uses the real Google API and may
  incur charges, but never opens the microphone or inserts text. Separate timings
  distinguish ASR finalization from cleanup; success does not test your own voice
  or destination editor.

To run the same fixed-sentence API test from Terminal after key/consent setup:
/Applications/OpenInsert.app/Contents/MacOS/OpenInsert --diagnose-pipeline
It never opens the microphone or inserts text. It exits when complete or after a
70-second overall deadline and prints JSON status, timings and the synthetic result.
Check the report's success field. No credentials or ordinary dictation are printed;
redirecting stdout to a file will preserve the synthetic test report.

Default ASR: gemini-3.5-transcribe-live (WebSocket, automatic language detection).
Default optional cleanup: gemini-3.5-flash-lite (text-only generateContent, minimal
thinking). Verbatim mode skips cleanup. Cleanup has an eight-second total limit;
while waiting, "略過後修，直接使用辨識結果" cancels cleanup and uses finalized ASR.
A skip or temporary cleanup failure uses that final text after the usual target
checks and reports the fallback. Cancelling the entire operation, permanent errors,
blocked or incomplete/invalid output stop automatic insertion. Unfinalized previews
are never inserted. Check the destination before manually copying results.

For the default dedicated ASR model, completion requires authoritative final text,
a successfully sent activityEnd, no unresolved interim and one second without text
updates. It no longer requires turnComplete for that exact model. Other models
retain that extra condition. A 20-second ASR deadline remains, separate from the
eight-second cleanup deadline. Quiet waiting is a heuristic, not a guaranteed
receipt for every late segment. Review important dictated text.

Audio uses bounded RAM buffers; OpenInsert 0.2 creates no recording files. There is
no screen context, screenshot capture or transcript history. Cancelling cannot
recall audio or text already sent to Google. API usage and data processing follow
your Google account's terms. Never share a key in an issue or screenshot.
Google's key guide: https://ai.google.dev/gemini-api/docs/api-key

This community build is ad-hoc signed, not Apple Developer ID signed or notarized.
macOS may block a downloaded build. Inspect the source or build locally if needed.
Do not disable Gatekeeper. See Apple's official guidance if you choose to open it:
https://support.apple.com/en-us/102445

Updating or rebuilding an ad-hoc build may require granting Accessibility again,
even when System Settings still shows the old entry enabled. If OpenInsert reports
permission off, quit old copies, remove the old OpenInsert Accessibility entry,
and add and enable the currently installed app (normally /Applications/OpenInsert.app).
Reopen that app and click Recheck Permissions. Connection & Permissions shows the
running app's path so you can identify the correct copy. OpenInsert never resets
or grants these system permissions automatically.

For source builders with an existing signing certificate, build-app.sh can read
its fingerprint from the first line of the gitignored .local-signing-identity at
the repository root. CODE_SIGN_IDENTITY takes priority. The file selects an existing
certificate/private-key identity on your Mac; it does not contain a private key.
Reusing a stable Apple Development identity can avoid repeated local permission
grants across rebuilds, subject to macOS policy. A first switch from ad-hoc signing
may still require permission again. This is not Developer ID signing or notarization.
Do not publish personal certificates, emails, fingerprints or private keys.
Public CI has no local identity file and retains its ad-hoc default.

OpenInsert validates the original input target through Accessibility, then uses
the clipboard and standard Command-V for every automatic insertion. It does not
write transcript text through AX attributes. With restoration enabled, readable
clipboard formats are backed up in memory and restored after 800 ms only if the
clipboard still has the app-owned version. With restoration disabled, the result
stays on the clipboard. No clipboard data is uploaded.

With Accessibility already granted, version 0.2.6 checks the target app's actual
AXManualAccessibility capability instead of requiring an Electron framework filename.
Only a writable Boolean false flag is enabled. If Manual is unavailable, an exact
NSPrincipalClass of BrowserCrApplication permits the Chromium AXEnhancedUserInterface
activation path; Manual permission/transport errors or invalid data do not qualify.
Activation is attempted once per identified target process launch during this
OpenInsert run. A successful setter allows a three-second preparation window;
it does not prove that an editable field is ready. No input content is read.
If preparation is reported, keep the target app focused, wait a few seconds, and
retry. The new initialization still requires validation in the affected editor.

The status confirms only that paste was requested, not that the editor accepted it.
There is no automatic AX write or second paste retry. When a completed dictation
has no valid input target or a supported error occurs before paste dispatch, OpenInsert copies the
finalized result automatically and shows a copied status in the floating panel.
Use Command-V yourself without reopening OpenInsert. This intentional copy replaces
the clipboard and is not restored, even if paste restoration is enabled. Normal
successful paste still uses the 800 ms guarded restoration described above.

Cancellation, missing final text and permanent provider errors do not trigger
automatic copy. Empty text or clipboard ownership/read/write failures also stop
further clipboard mutation; unknown errors and an already-dispatched paste do not
cause another copy. Only a successful write gets a copied status; otherwise an error
is shown and the final result remains in the app. The copied HUD lasts about six
seconds without activating the main window. Clearing the app result or quitting
does not clear the copied clipboard.

To exercise this behavior without microphone or Google, use the five-second fixed
text insertion test: it uses the same paste-or-copy delivery rules. Verify the
new behavior in your editor. Internal 0.2.5 was not released and still failed to
capture focus in the affected ChatGPT/Codex desktop app. The user confirmed a
spoken dictation directly in that input on 0.2.6. Repeated restarts and other
editors still require separate validation.
Automatic insertion does not work in every app. It never presses Return; destination
apps can still react to inserted text. The final result also stays available in
OpenInsert's result view. See docs/VALIDATION.md in the source
repository for the real-service and cross-app checks completed for this release.

The floating panel hides immediately after a standard paste is dispatched.
Automatic-copy and error notices remain visible so you can recover the result.
The clipboard restoration delay does not keep the panel over your input field.
